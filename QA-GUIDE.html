📋 API Migration Check Tool

A simple guide for QA testers to verify that our backend migration hasn't broken anything — no technical knowledge needed.

🤔 What is this tool?

When our team moves the backend to a new server, we need to make sure every API still works correctly and returns the same data. This tool does that check automatically.

😨 What you used to do

  • Open browser → login
  • Open Network tab → find API
  • Copy as cURL → paste in Postman
  • Run on old server, note the result
  • Change URL to new server, run again
  • Manually compare both results
  • Repeat 10+ times — takes hours

🎉 What this tool does

  • You login once in the browser
  • You click around the page normally
  • Tool captures all the APIs automatically
  • Calls both old and new server instantly
  • Compares results automatically
  • Generates a clear report
  • 10 APIs checked in ~5 minutes

⚙️ One-time setup (ask your developer)

Before you use the tool for the first time, a developer needs to set it up on your computer. This only needs to happen once.

What the developer will do:

  1. Install Node.js on your computer
  2. Open the project folder: api-capture-compare
  3. Run npm install in a terminal
  4. Fill in the .env file with the correct URLs and API names
✓ Once setup is done, you never need to touch any code or settings. Just run the commands below.

The .env file — what the developer fills in:

💡 Important: The website you log into and the APIs it uses are often on different addresses. For example, you might log in at app.company.com but the data APIs run on api.company.com. The tool handles this automatically — you only need to tell it where to log in and where the new API server is.
SettingWhat it meansExample
UI_URL The website address you log into. Used only for login and page navigation — not the API server. https://app.yourcompany.com
LOGIN_PATH The path to the login page (added to UI_URL) /login
TARGET_PATH The page to open after login. Leave blank if the URL changes every session — your QA tester will paste it at runtime. /dashboard
NEW_API_BASE The new API server address to test against. The tool takes every API call the page makes and replays it here. Only the server address changes — same request, same data, same token. https://new-api.yourcompany.com
AUDIT_APIS Which APIs to check — comma-separated path fragments. Only calls whose URL contains one of these will be captured. /api/patients,/api/offices
How it works behind the scenes:

You open: app.company.com → login → Page calls: old-api.company.com/api/patients → tool captures it → Tool replays: new-api.company.com/api/patients → compares results

▶️ How to run the check — step by step

1

Open a terminal in the project folder

On Mac: right-click the api-capture-compare folder → New Terminal at Folder
On Windows: open the folder → click the address bar → type cmd → press Enter

2

Type this command and press Enter

If your page URL has a dynamic key that changes every session, copy the full URL from your browser and paste it like this:

npm run audit -- --url "https://app.yourcompany.com/dashboard?APP_KEY=paste-your-key-here"

If the URL is always the same, just run:

npm run audit
💡 Where to find your URL: after logging in, look at your browser's address bar and copy the full address including everything after the ?
3

A browser window will open automatically

First time only: the login page opens. Log in with your normal credentials.
Come back to the terminal and press Enter.
Next time, the tool will remember your session automatically.

🔒 Your login is saved only on your computer. It is never shared or uploaded anywhere.
4

Use the page normally

The browser will navigate to the correct page. Just interact with it as you normally would — apply filters, click buttons, open sections. The tool is silently watching in the background and will pick up the API calls automatically.

🔎 You will see API calls being printed in the terminal as they happen. This is normal.
5

Press Enter in the terminal when done

Once you've triggered all the actions you want to test (e.g. applied a filter, opened a report), go back to the terminal and press Enter.

The tool will automatically call the new server with the same requests and compare the results.

6

Open the report

A file called audit-report.html will appear in the project folder. Double-click it to open in your browser.

📋 Share this file directly with your team — just attach it to an email or upload to your test management tool.

📄 What to do with the results

If everything is PASS ✓

The new system is working correctly for all checked APIs. You can sign off on this migration.

Attach audit-report.html to your test evidence, Jira ticket, or email as proof.

If some APIs FAIL ✗

  1. Open audit-report.html and scroll to the red cards
  2. Each red card shows exactly what went wrong in plain English under "What needs to be checked"
  3. Raise a bug ticket with:
    • Title: use the API name shown on the card (e.g. "Dashboard Patients API — record count mismatch")
    • Description: copy the text from the "What needs to be checked" section
    • Attachment: attach the full audit-report.html file as evidence
  4. After the developer fixes the issue, run npm run audit again to re-verify
⚠ Do not sign off if any APIs are showing FAIL. Even if the UI looks correct visually, the data returned by the API may be wrong.

❓ Common questions

Do I need to log in every time I run the tool?
No. After you log in the first time, your session is saved. The next time you run the tool, it will skip the login automatically. If your session expires, it will ask you to log in again.
The page URL changes every time I log in. What do I do?
Copy the full URL from your browser after logging in, then run the command like this:
npm run audit -- --url "paste-your-full-url-here"
I don't see any APIs being captured. What's wrong?
Make sure you actually interacted with the page after it loaded — click a filter, open a tab, or trigger an action. The tool only captures APIs that fire while you're using the page.
Can I test multiple pages in one run?
Yes. After the browser opens, you can navigate to as many pages as you want. The tool will capture all matching API calls across all pages until you press Enter.
Where is the report saved?
The report is saved as audit-report.html inside the api-capture-compare project folder. It's a regular HTML file — just double-click it to open in any browser. You can email it or share it like any other file.
Is my password stored anywhere?
No. The tool only saves your browser session (cookies) in a file called browser-state.json on your computer. Your actual username and password are never stored.
Something went wrong and I want to start fresh. What do I do?
Delete the file browser-state.json from the project folder. The next run will ask you to log in again from scratch.
