📋 API Audit Tool — QA Guide

Everything you need to run the audit and understand your report — no technical background required.

🔍 What does this tool do?

When your backend APIs are moving to a new server, someone needs to check that the new server returns the same data as the old one. Normally a QA tester would:

  1. Open the browser network tab
  2. Find an API call and copy it as cURL
  3. Paste it into Postman
  4. Change the URL to the new server
  5. Compare the results manually

This tool does all of that automatically — just use your app normally and press Enter when done. It checks every API you care about and gives you a colour-coded report.

▶ How to run the audit

1
Open a terminal in the project folder
In VS Code / Cursor: press Ctrl+` (backtick) to open the terminal.
2
Type the command and press Enter
npm run audit
A browser window will open automatically. Do not close it yet.
3
Log in to the app (first time only)
The browser opens on the login page. Log in as you normally would. The tool detects when you are logged in — you do not need to do anything in the terminal.
✓ After the first run your session is saved. On the next run the browser opens directly on the app — no login needed.
4
Navigate the app normally
Open the pages you want to test. Apply filters, open sections, scroll through lists — anything that triggers an API call. The terminal will show each API call as it is captured:

[→] GET https://old.app.com/api/v1/offices
[←] 200 https://old.app.com/api/v1/offices
[↔] 200 https://new.app.com/api/v1/offices
  Status ✓  Keys ✓  Rows ✓  (42 → 42 via "total" field)
5
Press Enter in the terminal when done
Come back to the terminal (not the browser) and press the Enter key. The tool will close the browser and generate your report.
You will see: [audit] ✅ Done! with links to the report files.
6
Open audit-report.html in your browser
Double-click the audit-report.html file in the project folder, or drag it into a browser window. This is your full QA report.

🗂 Run history — your previous reports are always saved

Every time you run the audit, the previous report is automatically archived into a timestamped folder. You never lose old results.

📁 The responses/ folder inside each run contains the raw API responses — both old and new — so you can open them and see exactly what each server returned.

📊 How to read the report

The report has one card per API endpoint. Each card is either green (PASS) or red (FAIL).

Offices  ·  GET · API #1 ✓ PASS
Old: 42  →  New: 42   ✓ Match Counted via: "total" field

✓ Structure and count look correct.
Patients  ·  GET · API #2 ✗ FAIL
Old: 150  →  New: 148   ▲ Count differs
What needs attention:
  • Count mismatch (via "total" field): old = 150, new = 148
  • New system is missing fields: data.items.insuranceId, data.items.referralCode
Missing fields   data.items.insuranceId data.items.referralCode
What you seeWhat it means
✓ PASS (green)New server returns the same structure and count as old server
✗ FAIL (red)Something is different — see the details inside the card
Count mismatchThe number of records is different between old and new
Missing fields (red chips)The new server is not returning these data fields
Extra fields (blue chips)The new server returns extra fields the old one did not have
"Counted via: object key count"The API has no count field — the tool counted the top-level keys instead
Could not reach new systemThe new server URL may be wrong, or the server is down

🔬 What exactly is compared?

The tool does not compare actual values (e.g. a patient's name). It only checks structure and counts.

What is checkedExamplePass if…
HTTP Status 200 OK, 401 Unauthorized Both old and new return the same status code
Record count 42 patients returned Old and new return the same number
Nested keys data.items.id, data.items.name, meta.total Both responses have the same set of field names at every level
💡 Nested keys means the tool checks every field path — not just the top level. For example, if data.items.address.city exists in the old response but not in the new one, it will be flagged as missing.

🛠 Troubleshooting

ProblemWhat to do
No API calls appear in the terminal Check that AUDIT_APIS in your .env file contains the correct path patterns (e.g. api/v1/offices)
Browser does not open Run npx playwright install chromium and try again
Login page keeps showing on every run Delete browser-state.json and log in again
My page URL has a code like ?APP_KEY=abc123 Run: npm run audit -- --url "https://your-app.com/page?APP_KEY=abc123"
All APIs show "Could not reach new system" Check NEW_API_BASE in your .env file — make sure the new server URL is correct
Want to check different APIs this run Run: npm run audit -- --apis "api/v1/payments,api/v1/employees"

⚡ Quick reference

Standard run

npm run audit

Opens browser, uses session if saved.

Dynamic URL

npm run audit -- --url "https://..."

Use when URL has a dynamic key.

Reset session

Delete browser-state.json and run again — login page will appear.

Find old reports

Look in audit-runs/ folder — each subfolder is a previous run with full responses saved.

Override APIs

npm run audit -- --apis "api/foo,api/bar"

Override new server

npm run audit -- --newBase "https://new.example.com"
